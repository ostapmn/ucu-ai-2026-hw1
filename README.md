## Відтворення

```bash
pip install -r requirements.txt

python src/data.py

# 3. ноутбуки по порядку

```

`python src/data.py` виконує чек-ліст підготовки (`validate_preparation`) і падає з
`AssertionError`, якщо щось не так: порушена цілісність розрізу, не застосувалася
нормалізація, зникли пропуски або зсунулися рівні категорій.

## Відтворюваність

- `SEED = 42` у `src/config.py`, використовується в спліттерах і моделях.
- `KFold(n_splits=5, shuffle=True, random_state=42)` створюється в одному місці
  (`cv.get_folds`) і імпортується всюди.
- Версії пакетів зафіксовані в `requirements.txt` (Python 3.13.5, arm64 / macOS).
- Підготовлені parquet детерміновані: той самий seed дає той самий розріз.

## Протокол валідації

**Три рівні даних.**

| Набір | Рядків | Призначення |
|---|---:|---|
| `train_dev.parquet` | 396 900 | уся розробка: CV, вибір моделі, фіч, гіперпараметрів |
| `holdout.parquet` | 44 100 | **не чіпається** до фіналу; одна чесна оцінка 2–3 кандидатів |
| `test.parquet` | 189 000 | сабмішн на Kaggle (30% публічний / 70% приватний лідерборд) |

**Два протоколи CV.**

- **Protocol A (benchmark)** — 5 фолдів на повних `train_dev`. Усі числа для звіту.
- **Protocol B (search)** — 3 фолди на підвибірці 150 000. Лише для ранжування
  гіперпараметрів; переможець завжди переміряється за Protocol A.

**Дисципліна holdout.** `data.load_holdout()` викликається тільки з
`05_final_submission.ipynb`. Перевірка перед здачею:

```bash
grep -rn "load_holdout\|holdout.parquet" notebooks/   # має знайтись лише в 05
```

**Fold-safe препроцесинг.** Детерміновані операції (`strip`/`lower`, арифметика фіч,
`clip` до меж із домену) виконуються до CV. Усі навчені (`SimpleImputer`,
`StandardScaler`, `OneHotEncoder`) живуть у `sklearn.Pipeline` і фітуються всередині
навчальної частини кожного фолду.

`run_cv()` приймає **фабрику** моделі (callable без аргументів), а не готовий об'єкт:
інакше на другому фолді модель дофітувалася б поверх стану з першого, і валідаційні
рядки першого фолду вже брали б участь у навчанні.

### Усереднення по random_state

| сідів | XGBoost | LightGBM |
|---:|---:|---:|
| 1 | 8.9190 | 8.9259 |
| 8 | **8.9156** | **8.9221** |

Безкоштовний виграш −0.0034: `subsample=0.7` робить результат залежним від сіда, і ця
дисперсія прибирається усередненням кількох запусків (усередині кожного фолду).

**Ключове спостереження:** одна seed-усереднена XGBoost (8.9156) **обійшла стек із
п'яти різних моделей** (8.9168). Бленд двох seed-усереднених не кращий за одну. Причина:
усереднення по сідах і стекінг роблять одну роботу — знижують дисперсію, — а бустинги
в нашому стеку відрізнялися саме випадковістю підвибірок (кореляція залишків 0.996+).

**Внески за джерелами:** фічі −0.0696, гіперпараметри −0.0186, моделі й ансамблі −0.0102,
усереднення по сідах −0.0034.

### Фінал (ноутбук 05) — перевірка на незайманому holdout

| кандидат | OOF | holdout | файл |
|---|---:|---:|---|
| **A стек, XGB+LGBM по 8 сідів** | **8.9152** | — ¹ | `sub_final_A_stack_seedavg.csv` |
| **B XGBoost + нативні NaN, 8 сідів** | **≈ 8.9156** | — ¹ | `sub_final_B_xgb_seedavg.csv` |
| A стек, 1 сід (історія) | 8.9168 | 8.9133 | `sub_final_A_stack.csv` |
| B XGBoost, 1 сід (історія) | 8.9186 | 8.9147 | `sub_final_B_xgb.csv` |

¹ holdout використано **один раз** — для односідової пари. Усереднення по сідах не є
вибором між варіантами (дисперсія монотонно спадає з кількістю сідів), тож повторна
перевірка не потрібна, а holdout зберігає незалежність. Прогнози усереднених і
односідових версій корелюють вище 0.999.

Holdout виявився **кращим** за CV-оцінку на 0.0035–0.0039 — ознак переобучення
крос-валідації під 155 використань немає. Але він також показав, що **виграш від
стекінгу не підтверджується**: одиночний XGB native на holdout дав 8.9132, тобто стек
не кращий за свою найсильнішу складову.

Подаються обидва кандидати: вибір одного за holdout перетворив би його на селектор і
позбавив незалежності. Кореляція прогнозів A і B на test — 0.9998.


## Ключові знахідки EDA (ноутбук 01)

Повний список «спостереження → рішення» — у розділі 10 ноутбука. Чотири найважливіші:

1. **`study_time` пошкоджений множником рівно 4.** 804 рядки мають `study_time` у 4 рази
   завищений (медіана множника 3.9991). Це не викиди, а детермінована помилка: `study_time/4`
   відновлює години з точністю 11.6 хв — на рівні власного шуму вимірювання. Інформація не
   втрачена, рядки видаляти не треба. → FE-1
2. **`engagement_index` — похідна фіча без власної інформації.** На 95.7% пояснюється
   рештою числових фіч (`study_minutes` + `attendance_rate` дають R² = 0.9565). Кореляція
   її **залишку** з таргетом 0.029 проти 0.736 у самої фічі — зв'язок позичений. VIF = 23.1.
   → FE-2: видалити, очікувана втрата ≈ 0
3. **Таргет цензурований.** Точкові маси рівно на 100.0 (2.46%) і рівно на 19.599 (1.00%).
   Клампінг прогнозів робимо в `[19.599, 100.0]`, не `[0, 100]`.
4. **Зв'язки майже лінійні** (Pearson ≈ Spearman, рівні кроки по квантильних корзинах).
   Прогноз: лінійна регресія близька до оптимуму, одиночне дерево має їй програти, приріст
   бустингу скромний.

Плюс: 7 із 15 фіч не пов'язані з таргетом; пропуски MCAR (missing-індикатори передбачувано
не допоможуть); adversarial AUC = 0.5001 (зсуву train/test немає); вбудована важливість
LightGBM ставить шумовий `intake_marker` на 4-те місце з 15 — використовувати permutation
importance.
